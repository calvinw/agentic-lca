    Plan for Reference LCA Teaching Examples

    Purpose

    This document defines the format and content of the completed reference case studies used in this project. Each case study is a self-contained teaching package that provides enough information for an LLM-powered teaching skill to walk a student through any part of the LCA methodology using real numbers from that product.

    The cases are designed for students at FIT (Fashion Institute of Technology) — business and retail management students with no programming background.

    Folder Location

    The reference teaching examples live in skills_references/ in the project root — separate from lca_analysis/, which holds examples tied to the openLCA server calculation workflow.

    skills_references/
  wool_yarn/
  polyester_tshirt/
  cotton_fiber/
  ...

    The teaching skills read from skills_references/<name>/ when given a case study argument. This keeps curated teaching material separate from ad-hoc analysis runs.

    Folder Structure (per case study)

    skills_references/<product>/
  recipe_card.md              ← supply chain spec + LCIA method + characterization factors
  lca_results.md              ← pre-computed results: scaling vector, impacts by process and indicator
  product_graph_scaled.svg    ← supply chain diagram with scaling factors and flow amounts
  product_graph_structure.svg ← supply chain diagram with flow names only (no numbers)
  notes.md                    ← written teaching document: damage pathways, business narrative

    File Descriptions

    recipe_card.md

    The single quantitative source of truth for the case study. Contains two parts:

    Part 1 — YAML frontmatter (the supply chain spec): - name — product name and functional unit description - goal — the study goal in plain language - functional_unit — what exactly is being measured (description, amount, unit) - units — unit definitions - products — all intermediate and final products in the supply chain - elementary_flows — emissions to air/water and resource extractions from nature - processes — each step in the supply chain with inputs, outputs, emissions, resources - reference_process — the process that delivers the functional unit - lcia — LCIA method name and impact categories with characterization factors (see below)

    Part 2 — Markdown body (study notes): - Key assumptions table - Simplifications made - Source references - Any teaching notes specific to this product

    The lcia: section format:

    Simple (climate only):

    lcia:
  method: IPCC AR6
  impact_categories:
    - name: Climate change
      indicator: GWP100
      unit: kg CO2 eq
      characterization_factors:
        CO2 to air: 1.0
        CH4 to air: 27.9

    Multi-indicator:

    lcia:
  method: EF 3.0
  impact_categories:
    - name: Climate change
      indicator: GWP100
      unit: kg CO2 eq
      characterization_factors:
        CO2 to air: 1.0
        CH4 to air: 27.9
        N2O to air: 273.0
    - name: Eutrophication (terrestrial)
      indicator: EP-terrestrial
      unit: mol N eq
      characterization_factors:
        NH3 to air: 3.54
        N2O to air: 0.27

    The method name (e.g., "EF 3.0", "IPCC AR6") is the published standard the factors come from. The factors are embedded in the recipe card so calculations work without requiring the LCIA method to be loaded in the openLCA database. The factors must match the named standard's published values.

    lca_results.md

    Pre-computed once (requires the openLCA server) and committed to the repository. Regenerate only when the recipe card changes. Contains:

    • Goal and scope statement
    • Reference flow vector f
    • Technology matrix A
    • Scaling vector s = A⁻¹ · f (how much each process runs per functional unit)
    • Intervention matrix B (emissions per unit of each process)
    • LCI results B · s (total emissions per functional unit)
    • LCIA results (characterization factors applied — totals per impact category)
    • Contribution analysis (which process drives which impact, as a percentage)

    product_graph_scaled.svg

    Generated by lca_scripts/lca_svg.py from the recipe card. Shows: - Each process as a labelled box - Scaling factor (s) on each box - Flow amounts on each arrow between processes - Emissions and resource flows as coloured side arrows

    product_graph_structure.svg

    Generated by lca_scripts/lca_svg.py --structure from the recipe card. Shows: - Each process as a labelled box - Flow names on arrows (no quantities) - Clean overview of supply chain structure

    notes.md

    A written teaching document. Not generated — written by hand (or LLM-assisted). Contains:

    1. LCIA method explanation — what EF 3.0 or IPCC AR6 is, why it was chosen for this product, what the indicators mean in plain language

    2. Damage pathways — for each impact category, the full chain: emission → atmospheric/ecological mechanism → midpoint indicator → endpoint damage

    Example for N2O: - N2O emitted from fertilised soil - Acts as a greenhouse gas (radiative forcing) AND depletes stratospheric ozone - Midpoint: GWP100 = 273 kg CO2 eq per kg N2O - Endpoint: climate change (human health, ecosystem quality) + UV exposure

    1. Key findings — the main numbers, written for a business student: which process dominates, what surprised us, how the result compares to everyday reference points (km driven, days of electricity use, etc.)

    2. Business relevance — what a sourcing, procurement, or product design decision could change based on this result

    The Three FIT Reference Case Studies

    These three cases are designed as a teaching progression. Each adds exactly one new concept. All are directly relevant to fashion and textiles.

    Case 1 — Wool yarn (1 layer deep, climate only)

    Folder: skills_references/wool_yarn/

    Supply chain:

    P1: Sheep farming  →  P2: Wool yarn production  [reference]

    Depth: 1 layer. The sheep farm is one upstream node from the reference process. The scaling is straightforward: to produce 1 kg of yarn, you need 1.1 kg of raw fleece (10% waste in scouring and spinning), so the sheep farm runs at scale 1.1.

    Emissions: - P1 (Sheep farming): CO2 (farm energy), CH4 (enteric fermentation — sheep digestion) - P2 (Wool yarn): CO2 (scouring, spinning energy)

    LCIA method: IPCC AR6, GWP100 only

    Key teaching moment: Sheep methane. CH4 has a GWP of 27.9 — nearly 28 times more potent than CO2. Wool's "natural" reputation does not mean low-carbon.

    Case 2 — Polyester T-shirt (2 layers deep, climate only)

    Folder: skills_references/polyester_tshirt/

    Supply chain:

    P1: Oil extraction  →  P2: Polyester fiber production  →  P3: T-shirt assembly  [reference]

    Depth: 2 layers. Oil extraction is two hops back from the finished T-shirt. Calculating the oil extraction's contribution requires compound scaling: how much fiber per shirt × how much oil per kg of fiber.

    Emissions: - P1 (Oil extraction): CO2 (combustion of energy), CH4 (fugitive from wells) - P2 (Polyester fiber): CO2 (polymerisation, energy; ~1.5 kg oil per kg fiber) - P3 (T-shirt assembly): CO2 (cutting, sewing, factory energy)

    LCIA method: IPCC AR6, GWP100 only

    Key teaching moment: "Your T-shirt is oil." Polyester is a petroleum product. The matrix inversion shows how the emissions from the oil well end up attributed to the shirt, even though the well is two steps back in the supply chain.

    Case 3 — Cotton fiber (1 layer, multi-indicator)

    Folder: skills_references/cotton_fiber/

    Supply chain:

    P1: Fertilizer production  →  P2: Cotton farming  [reference]

    Depth: 1 layer. Same structural depth as wool yarn — but this case introduces a second impact category, making the LCIA step the main teaching focus.

    Emissions: - P1 (Fertilizer): CO2 (energy-intensive production of synthetic nitrogen fertilizer) - P2 (Cotton farming): CO2 (machinery, irrigation energy), N2O (from fertilised soil — microbial conversion of nitrogen), NH3 (volatilisation from soil)

    LCIA method: EF 3.0, two impact categories: - Climate change (GWP100): CO2, N2O, CH4 - Terrestrial eutrophication (EP-terrestrial): NH3, N2O

    Key teaching moment: Cotton has a natural reputation but the field is the problem. N2O from the soil is 273× more potent than CO2 per kg. NH3 causes eutrophication — excess nitrogen in soil and waterways — independently of its climate contribution. The same emission (N2O) hits two different impact categories at once.

    Teaching Skills (planned)

    Six teaching skills are planned, one per LCA concept. Each skill accepts a case study name as an argument (e.g., /functional-unit wool_yarn) and reads the relevant files from skills_references/<name>/ to teach from real data.

    Skill Concept Primary file(s) used
    functional-unit What is being measured and why that unit was chosen recipe_card.md
    supply-chain Reading the product diagram — processes, flows, connections recipe_card.md + structure SVG
    scaling-vector How much each process runs to deliver exactly 1 functional unit recipe_card.md + lca_results.md
    lcia-method What the impact categories mean and how characterization works recipe_card.md + lca_results.md
    damage-pathway The chain from emission → mechanism → real-world harm notes.md
    hotspots Which process dominates and what a business could change lca_results.md + notes.md

    Design principle

    All skills are written generically. The product-specific knowledge lives in the case study files — recipe card, results, notes. The skill only knows how to teach the concept, not the facts about any specific product. This means: - Adding a new case study folder makes it immediately available to all skills - Updating a recipe card automatically updates what the skill teaches - The skill file never needs to be edited when examples change

    Implementation Order

    1. Create the skills_references/ folder in the project root

    2. Build the three case study folders inside it (wool_yarn, polyester_tshirt, cotton_fiber):

    3. Write recipe_card.md with lcia: section
    4. Run lca_svg.py to generate both SVGs (no server needed)
    5. Run lca_analysis.py to generate lca_results.md (requires openLCA server)

    6. Write notes.md with damage pathways and business narrative

    7. Write the functional-unit skill generically and test it against all three cases

    8. Write remaining skills in the order listed above, testing each against the three cases

    9. Optionally extend to existing case studies (coffee, apple, hoodie, popcorn, polystyrene) by adding them to skills_references/ with lcia: sections and notes.md
